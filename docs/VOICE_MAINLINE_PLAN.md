# 语音主产品线方案（2026-03-14）

## 当前判断

主产品线不再以 `Ditto` 或“先生成视频再播放”为中心，而是优先追求三件事：

1. 像真正通话的低延迟语音交互
2. 中文稳定、成熟、偏年长的男声
3. 后续可迁移到“父亲本人声音”

## 结论

当前最优路线应拆成两层：

### 1. 当前可上线主线

- `浏览器录音`
- `STT`
- `DeepSeek / 对话主脑`
- `TTS`
- `浏览器本地 Web 2D 动画`

这层继续保持轻量，不把视频渲染塞回默认链路。

### 2. 下一阶段语音主线

优先准备 `阿里云实时语音`，原因不是“供应商偏好”，而是更贴近当前目标：

- 中文语音更稳
- 更容易拿到成熟男声
- 后续存在语音克隆能力，可衔接“父亲本人声音”
- 官方能力已经覆盖实时 ASR / 实时 TTS / 语音克隆，不需要长期把主路线绑死在实验视频链路上

OpenAI 继续保留为：

- 当前 STT 的已跑通备线
- 当前 TTS 的已跑通备线
- 当阿里云 key、声音、或实时链路未就绪时的稳定回退

## 分阶段落地

### Phase A：收紧当前主线

- `STT` 使用可配置服务，不再写死旧模型
- `TTS` 继续维持 `aliyun -> openai -> edge` 的明确优先级
- 前端继续保持 `Web 2D` 单主舞台，避免结构重新变乱

### Phase B：接实时语音

- 优先接 `阿里云实时 ASR + 实时 TTS`
- 页面交互改成更像通话的“边说边收、边答边播”
- `DeepSeek` 暂时仍可保留为中间文本主脑，先把实时体验做好

### Phase C：接近父亲本人声音

- 在成熟男声稳定后，再进入语音克隆
- 语音克隆只作为后续升级，不应阻塞当前上线体验

## 当前工程约束

- 阿里云服务器主控制方式固定为 `SWAS RunCommand`
- 主站当前是 `https://liyong828.com`
- `Ditto` 保留实验支线，但不再定义默认用户路线
- 所有主线改动完成后都要同步：
  - `README.md`
  - `memory-hub`
  - GitHub push

## 供应商结论依据

- OpenAI 官方文档：
  - Realtime API 支持低延迟语音对话
  - 当前转写模型可用 `gpt-4o-mini-transcribe`
- 阿里云 Model Studio / DashScope 官方文档：
  - 已提供实时语音识别能力
  - 已提供 `qwen-tts` 语音合成能力
  - 已提供 CosyVoice 语音克隆能力

所以当前工程判断不是“OpenAI 不行”，而是：

- `OpenAI` 更适合继续做现阶段已打通的稳定备线
- `阿里云` 更适合作为下一阶段中文实时通话主线
